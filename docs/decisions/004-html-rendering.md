# ADR-004: استراتيجية عرض HTML

**الحالة:** مقبول
**التاريخ:** 2026-09-30
**صاحب القرار:** عمرو محمد (المشرف)
**يُكمل:** ADR-001 (المكدس التقني)

## السياق

حاليًا، بعد جلب صفحة، نعرض محتواها كنص خام في عنصر نصي. هذا بعيد عن تجربة المتصفح الحقيقية: لا تنسيق، لا روابط قابلة للنقر، لا عناوين بارزة.

المشروع يحتاج قرارًا معماريًا: كيف نعرض HTML؟

## الخيارات المدروسة

### الخيار الأول: محرك عرض كامل

تنفيذ محلل HTML كامل، ومحرك CSS، ومحرك تخطيط، ومحرك رسم. هذا هو الهدف النهائي، لكنه يحتاج أشهرًا من العمل.

**رُفض في الوقت الحالي.** لا يتناسب مع المرحلة صفر.

### الخيار الثاني: عرض عناصر HTML كأدوات واجهة

تحليل HTML بسيط، ثم تحويل كل وسم إلى عنصر واجهة مناسب:

- `h1` إلى `h6` ← نص بخط كبير.
- `p` ← نص عادي.
- `a` ← زر رابط.
- `ul`، `ol`، `li` ← حاويات ونصوص.
- `br` ← فاصل.

**مقبول.** نتيجة مرئية، تنفيذ ممكن، وأساس للتوسّع.

### الخيار الثالث: استخراج نص نظيف

إزالة وسوم HTML، وعرض النص المجرد.

**رُفض.** يفقد كل التنسيق.

## القرار

نعتمد **الخيار الثاني**: عرض عناصر HTML المختارة كأدوات واجهة.

## النطاق

**الوسوم المدعومة في البداية:**

- `h1` حتى `h6`: عناوين.
- `p`: فقرة.
- `a`: رابط.
- `ul`، `ol`: قائمة نقطية أو مرقمة.
- `li`: عنصر قائمة.
- `br`: فاصل سطر.
- `strong`، `em`: تمييز.
- `span`، `div`: حاويات.

**خارج النطاق حاليًا:**

- CSS، بكل أشكاله.
- الجداول.
- الصور.
- النماذج.
- الإطارات.
- JavaScript.

## النتائج المترتبة

- سنبني محلل HTML بسيطًا في `src/renderer/html/`.
- سنبني عارضًا في `src/renderer/` يحوّل الشجرة إلى أدوات جي تي كي.
- سنستبدل عرض النص الخام في النافذة بالعرض الجديد.
- أي وسم غير مدعوم يُعامَل كحاوية شفافة: نعرض أبناءه بلا تنسيق خاص.
- عند إضافة محرك CSS لاحقًا، سنوسّع المحلل والعارض.
