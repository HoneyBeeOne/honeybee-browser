# ADR-003: لغة README

**الحالة:** مقبول
**التاريخ:** 2026-09-22
**صاحب القرار:** عمرو محمد (المشرف)
**يُكمل:** ADR-002 (سياسة اللغة في المشروع)

## السياق

في ADR-002، قررنا أن التوثيق يُكتب بالعربية في الوقت الحالي، لأن الجمهور المستهدف ناطق بالعربية.

لكن عند ترجمة README إلى العربية (PR #42)، ظهرت مشكلة عملية: **GitHub لا يدعم RTL (من اليمين إلى اليسار) في عرض ملفات README**. الملف العربي يُعرض من اليسار إلى اليمين، ما يجعل القراءة صعبة، ويجعل الشارات والقوائم والعناوين تظهر بمحاذاة غير طبيعية.

جرّبنا حلًا عبر تغليف المحتوى في `<div dir="rtl" align="right">` (PR #44)، لكن النتيجة لم تكن مرضية. GitHub لا يطبّق الاتجاه على كل عناصر Markdown (خصوصًا الشارات، القوائم، والعناوين)، فبقي العرض مشوّهًا.

## القرار

نعتمد سياسة لغوية مخصّصة حسب نوع الملف:

| الملف | اللغة |
|---|---|
| `README.md` | الإنجليزية |
| `CONTRIBUTING.md` | العربية |
| `docs/*.md` | العربية |
| `docs/decisions/*.md` | العربية |
| التعليقات في الكود | العربية مفضّلة، والإنجليزية مقبولة (كما في ADR-002) |
| أسماء المتغيرات والدوال ورسائل الـ commit | الإنجليزية (كما في ADR-002) |

## المبرر

**README بالإنجليزية:**
- هو أول ما يراه أي زائر، من أي بلد.
- يُقرأ في المتصفح حيث لا يمكن تجاوز قيود RTL.
- عرضه الصحيح أهم من لغته، لأن الهدف منه هو التعريف بالمشروع.
- المساهمون المحتملون من خلفيات لغوية مختلفة (كما حدث مع `isaim0011`) يجدون فيه مرجعًا موحّدًا.

**CONTRIBUTING و docs بالعربية:**
- تظهر أقل بكثير من README.
- تُقرأ مرة واحدة عند أول مساهمة.
- فقراتها قصيرة ومقسّمة، فلا تتأثر بمشكلة RTL بدرجة كبيرة.
- مخاطبتها بالعربية تعزز انتماء المساهم المحلي.

## البدائل التي دُرست

**البديل الأول: README بالعربية مع `<div dir="rtl">`.**
رُفض بعد تجربة فعلية في PR #44، لأن النتيجة لم تكن مرضية بصريًا.

**البديل الثاني: README بلغتين، ملفان منفصلان (`README.md` و `README.ar.md`).**
مؤجل. يمكن النظر فيه لاحقًا إذا كبر المشروع وزاد عدد المساهمين الناطقين بالعربية.

**البديل الثالث: تعديل ADR-002 مباشرة.**
رُفض. القرارات في ADR لا تُعدّل، بل يُضاف قرار جديد يخصصها أو يلغيها. هذا يحفظ تاريخ التفكير، ويشرح للقارئ *لماذا* تغيّر القرار.
